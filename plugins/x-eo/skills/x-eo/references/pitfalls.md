# Pitfalls (each one cost real time)

1. **Host-root-only files.** `robots.txt`, `llms.txt`, `/.well-known/*`, `/ai/*` are read at the host root only. A project site at `user.github.io/project/` has none of them from the crawler's point of view; tools report "llms.txt not found" and your `Sitemap:` line in `/project/robots.txt` is never read. Fix: root site/repo (GitHub: `<user>.github.io`), or a root-level file on your host. A sub-path site that only redirects from root should keep `canonical` pointing at the real page.
2. **Search Console URL-prefix properties.** A property for `https://host/project/` rejects a sitemap at `https://host/sitemap.xml` ("sitemap address invalid"). Submit sitemaps inside the prefix; let root `robots.txt` advertise the root one. Domain properties need DNS TXT, impossible on `github.io`.
3. **Template pollution.** If one file is both the template and the generated output (e.g. `index.html` regenerated in place), writing prerendered content into it makes the *next* build copy that content into every other generated page. Wrap generated regions in markers (`<!--pre-->…<!--/pre-->`), strip them when reading the template, and prove idempotency: hash the file after build #1, #2, #3.
4. **Empty root, filled siblings.** Prerender pipelines often cover generated pages but not the hand-written root. Compare JS-on vs JS-off content for *each* template (`x-eo-verify/scripts/render-diff.mjs`).
5. **Tool path assumptions.** Checkers look for exact paths and shapes: `llms.txt` links must be markdown `[name](url)` (plain `- x: url` counts as zero links); `/ai/service.json` needs a `capabilities` list; `/ai/summary.json` needs `name` and `description`. Read the checker's scoring code before editing files to satisfy it — and remember these are Tier C.
6. **Wildcard-only robots.** `User-agent: * / Allow: /` allows everything, but some checkers only credit explicit per-bot groups. Spelling out `Allow` per bot is behaviour-neutral. Never add a `Disallow` while doing it; count them (`grep -c '^Disallow'`).
7. **Scripts inside HTML fool link checkers.** String fragments like `'+url+'` inside `<script>` look like `href` values. A "broken link" finding may be a regex artifact.
8. **Third-party tools run your machine's code.** Use a venv, pin the version, read install scripts, beware tools that install global agents/skills (name collisions overwrite silently) or hooks that fire on every edit. Prefer `git clone` + read over `curl | bash` — including for uninstall.
9. **Local testing of an audit tool.** Good tools refuse private/loopback targets (SSRF protection). For your own dev server, patch the guard in-process only (`x-eo-verify/scripts/local-audit.py`, opt-in env var) — never weaken it in the installed package.
10. **Dates you can't back.** Build time ≠ content-modified time. Do not emit `dateModified` from the build clock to win a freshness point.
11. **"UGC injection surface" by class name.** Scorers flag ids/classes that merely *look like* comment widgets (`respond`, `comments`, `review-list`) as third-party-writable regions. A static section named `.respond` with no form, input or server write is not an injection surface. Before reporting a SEC finding, confirm an actual write path exists (form/textarea/API). Renaming a class only to silence the heuristic is not worth touching site-wide CSS/JS.
12. **Site-level checkers start at the host root.** They crawl `https://host/` as "the home page". If that is a redirect stub (meta refresh to `/project/`), it scores as thin, no H1, no OG, no JSON-LD, and drags the whole report. Give the stub a real title/description, OG tags and an H1 with one sentence (canonical stays on the real page), or make the root a real page. They also treat `?query` URLs as separate pages, so a `?view=` link produces "duplicate title" findings that `canonical` already resolves — explain, don't rewrite.
13. **"Does AI know my site?" checks.** Calling a chat model *without* retrieval measures training-data recall, not search. Putting the brand or host in the question makes any "mentioned" check trivially true, and the description it produces is often invented. Measure instead: brand-free questions a real user would ask, retrieval-enabled APIs, and **a cited URL on your host** as the only positive (`x-eo-audit/scripts/ai-recall.mjs`). It is a sample, not a rate.
